# Sidera Content Studio Error Register

## Purpose

This file is the shared Content Studio failure register for every page-building session.

Every session must read this file before registering or editing Content Studio fields. When a new Content Studio failure appears, the owning session must diagnose it, add one row to this register, add a focused prevention test, and keep the row updated until the fix is verified.

Do not hide a failure inside the page activity note. Do not mark a page section ready for review while its Content Studio error is `OPEN`.

## Required Status

- `OPEN`: reproduced but not fixed.
- `FIXED`: root cause fixed and verified with a focused test plus real browser save.
- `REGRESSION`: a previously fixed error has returned.

## Mandatory Session Check

Run this before browser editing whenever a page adds or changes a Builder collection, entry, field, or locale:

```bash
node scripts/validate-content-studio-local.mjs
```

The command compares the current Builder registry with the initialized local D1 database.

- A failed check is blocking. It identifies a missing physical column that the runtime bootstrap cannot safely add to an existing table. Add a forward migration, apply it locally, and add an executable migration test.
- A warning identifies missing collection metadata, field metadata, table, entry, or locale bootstrap data. The editor's first Save draft request now forces a complete repair, but the page owner must still verify the save and persisted reload.
- A passing check does not replace browser verification.

## Mandatory Save Verification

For the first section and after every newly registered field set:

1. Use the real authorized page route on the shared local server. Do not start another server and do not verify only on `/demo`.
2. Run `node scripts/validate-content-studio-local.mjs`.
3. Enable Edit content and make one reversible temporary edit.
4. Save draft and confirm the state changes from unsaved to unpublished draft without an Error state.
5. Make a second save containing at least two changed fields from the same content target. This protects grouped payload handling.
6. Reload the preview and confirm the saved draft is present.
7. Restore every temporary value and Save draft again.
8. Open Review changes and confirm no unintended test copy remains.
9. Repeat one representative save-and-restore check for a non-English locale when the page introduces a new collection or locale binding.
10. Never publish verification copy.

If any step fails:

1. Stop page work and keep the page `IN PROGRESS`.
2. Open Content Studio Details and record the safe error message or HTTP status.
3. Reproduce the smallest failing field set.
4. Identify the root cause; do not blame punctuation, translated characters, or user copy without evidence.
5. Add an `OPEN` row below using the exact columns **ERROR**, **ERROR CAUSE**, and **FIX**.
6. Implement the smallest safe fix and add a focused regression test.
7. Run the preflight, focused tests, full tests, typecheck, build, and browser save-and-restore verification.
8. Change the row to `FIXED` only after every check passes.
